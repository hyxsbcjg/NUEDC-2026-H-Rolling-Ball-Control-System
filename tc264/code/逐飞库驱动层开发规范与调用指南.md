## 2. 驱动实现规则

- 单板固定的地址、引脚、速率和重试参数写成头文件宏；只有确有多板型或多实例需求时才增加运行时配置结构。
- 每个引脚、外设、通道和中断只能有一个所有者；新增驱动前先登记资源和冲突。
- 初始化顺序固定为：清状态、安全输出、总线、设备、身份或固定响应校验、异步事件源。
- CPU0 使用的持久状态显式放入 `cpu0_dsram`。
- 普通 ISR 只清标志并投递事件或调用一个最小回调；格式化输出、延时、阻塞 UART、协议解析和显示仍禁止进入 ISR。
- 固定周期控制 ISR 可按明确的控制时基要求直接完成传感器采样与控制算法，但必须保证总线单一所有者、无延时/重试，并实测最坏执行时间小于周期。当前灰度 Soft IIC 是这一受控例外。
- 所有等待必须有次数或时间上限；检查指针、长度、范围和底层返回值。
- 易失配置写入后回读；变长数据必须同时返回有效长度或有效掩码。
- 设备身份、固定响应、固件门槛、读清除寄存器和复位副作用必须写进接口说明。

## 4. 标准移植流程

每次移植按以下顺序执行：

1. **锁定基线**：记录目标工程、逐飞库版本、参考工程和手册版本。
2. **拆解协议**：列出地址或帧头、命令、方向、长度、字节序、返回值和副作用。
3. **映射目标 API**：
   - IIC：确认 7/8 位地址、参数顺序、START/STOP、重复 START 和 ACK 可见性；
   - UART：确认实例、波特率、数据位、校验、停止位、收发接口、回调和 FIFO。
4. **登记资源**：固定引脚、方向、所有者、服务 CPU、电平、速率和冲突。
5. **设计接口**：先定义公开 API、状态码和固定板级宏；无真实需求不引入配置结构。
6. **设计初始化**：清状态后初始化总线，用设备 ID、版本或固定响应确认在线，最后再开中断。
7. **限制等待**：把参考代码中的无限循环改为有限重试、超时和明确错误码。
8. **处理数据语义**：覆盖通道掩码、变长数据、字节序、校验、固件门槛、读清除和复位。
9. **限定上下文**：CPU0 状态放入 `cpu0_dsram`；严格周期采样、PID 和实时输出放入固定控制 ISR，其它阻塞或非实时操作留在初始化/前台。
10. **实现与源码核对**：检查声明/实现、参数、旧平台符号、危险接口、无界格式化、重复地址转换和资源冲突。
11. **生成用户验收清单**：列出 ADS 构建、Map、入口和上板步骤，不代替用户执行。
12. **更新移植记录**：写明基线、协议映射、关键适配、资源、调用方式、验证状态和电气约束。

### 6.1 基线

| 项目 | 当前实现 |
|---|---|
| 参考工程 | `../../docs/参考工程/灰度传感器/Std_Periphral/gw_gray_hw_i2c_软件IIC` |
| 目标底层 | `libraries/zf_driver/zf_driver_soft_iic.h/.c` |
| 驱动文件 | `code/gw_gray_sensor.h/.c` |
| 初始化 | `gw_gray_init(void)`，固定参数，无调用参数 |
| 地址 | 自动探测 7 位地址 `0x4C`～`0x4F`，命中 `0xAA -> 0x66` 后锁定使用 |
| 引脚 | SCL `P10.1`（`P10_1`），SDA `P10.3`（`P10_3`） |
| 时序 | Soft IIC 延时计数 `100`；Ping 最多 100 次，间隔 10 ms |
| 入口 | `my_menu_init()` 在 PIT 启动前初始化并使能全部 8 路；`my_task_service_irq()` 每 3 ms 读取数字量、计算权重误差并执行系数 `0.3` 的一阶低通，`my_menu_proc()` 只复制滤波后的最新快照并每 150 ms 刷新屏幕 |

固定宏位于 `gw_gray_sensor.h`：

```c
#define GW_GRAY_IIC_ADDRESS              (0x4CU)
#define GW_GRAY_IIC_ADDRESS_FIRST        (0x4CU)
#define GW_GRAY_IIC_ADDRESS_LAST         (0x4FU)
#define GW_GRAY_SOFT_IIC_SCL_PIN         (P10_1)
#define GW_GRAY_SOFT_IIC_SDA_PIN         (P10_3)
#define GW_GRAY_SOFT_IIC_DELAY           (100U)
#define GW_GRAY_PING_RETRY_COUNT         (100U)
#define GW_GRAY_PING_RETRY_INTERVAL_MS   (10U)
```

误差滤波固定宏位于 `gray_app.h`：

```c
#define GRAY_APP_ERROR_FILTER_ALPHA      (0.3F)
```

### 6.2 协议与接口

| 功能 | 命令 | 接口 | 关键语义 |
|---|---:|---|---|
| 在线探测 | `0xAA` | `gw_gray_ping()` | 响应必须为 `0x66` |
| 数字量 | `0xDD` | `gw_gray_read_digital()` | bit0～bit7 对应探头 1～8 |
| 全部模拟量 | `0xB0` | `gw_gray_read_analog()` | 返回已使能通道的紧凑数据 |
| 单通道模拟量 | `0xB1`～`0xB8` | `gw_gray_read_analog_channel()` | API 通道号为 1～8 |
| 通道使能 | `0xCE` | `gw_gray_get/set_channel_enable()` | 易失配置，写后回读 |
| 归一化 | `0xCF` | `gw_gray_get/set_normalize()` | 固件 V3.6 及以上，写后回读 |
| 固件版本 | `0xC1` | `gw_gray_read_firmware()` | 高 4 位主版本，低 4 位次版本 |
| 错误状态 | `0xDE` | `gw_gray_read_and_clear_error()` | 读取后清除 |
| 软件重启 | `0xC0` | `gw_gray_reboot()` | 重启后重新 Ping 并读取版本 |

关键适配：

- 参考 STM32 接口接收 8 位地址，所以使用 `0x4C << 1`；逐飞 `soft_iic_init()` 接收 7 位地址，本驱动直接使用 7 位地址，并自动探测 `0x4C`～`0x4F`。
- 逐飞 Soft IIC 公共接口不返回 ACK；普通接口返回成功只表示调用合法，设备在线需用 `0xAA -> 0x66` Ping 证明。
- 参考例程无限等待，本驱动改为约 1 s 的有限探测窗口；每轮先检查当前地址，再检查地址范围内的其它地址，成功后保留命中地址，全部超时返回 `GW_GRAY_STATUS_PING_TIMEOUT`。
- `0xB0` 的紧凑数据会展开到固定 8 字节数组；禁用通道写 0，`valid_mask` 标记有效项。
- `0xCE`、`0xCF` 写入后回读；不一致返回 `GW_GRAY_STATUS_VERIFY_FAILED`。
- 驱动状态放入 `cpu0_dsram`；Soft IIC 为阻塞操作。当前只在 PIT 启动前初始化，并由 3 ms 调度 ISR 每拍读取；PIT 启动后 CPU0 前台不得同时访问该总线。

### 6.3 调用

```c
uint8 digital_value;
gw_gray_status_enum status;

status = gw_gray_init();
if (GW_GRAY_STATUS_OK == status)
{
    status = gw_gray_read_digital(&digital_value);
}
```

当前菜单在 PIT 启动前显式写入并回读 `GW_GRAY_CHANNEL_ALL`，并允许一次初始化读。
PIT 启动后，`my_task_service_irq()` 每 3 ms 读取一次 `0xDD` 数字量并立即计算
权重误差；bit0～bit7 对应 CH1～CH8，黑线通道参与 `+3.5` 到 `-3.5` 的
对称权重平均。`gray_app_read()` 随后统一执行
`filtered += (raw_error - filtered) × 0.3`，并把滤波结果写回
`sample.error`。首次有效误差直接装载；通信失败或本拍 `error_num==0` 时输出
安全零值并清除滤波历史。原始误差不再对外发布，因此 task 快照、150 ms 屏幕
显示、`gray_app_get_error()`/`get_error()` 和 12 ms 循迹外环全部使用同一份
滤波结果，不会在 `track_control` 内再次滤波。12 ms 外环只复用最新采样结果，
不再访问 Soft IIC。

为避免前台 Ping 与控制 ISR 的 Soft IIC 事务相互打断，运行期前台 Ping 和自动重配已移除。逐飞 Soft IIC 不提供 ACK，因此普通 `0xDD` 读取不能作为在线证明；运行期掉线诊断需要后续设计不破坏 3 ms 控制时基的独占总线机制。

电气约束：

- 传感器使用 5 V 供电；SCL/SDA 跳线帽分别接通板载 10 kΩ、5 V 上拉，两个跳线帽均须安装。
- 逐飞 `soft_iic_init()` 默认将 SCL 配为推挽。本模块初始化后立即把 SCL 覆写为开漏；SDA 原本即为开漏，因此写高只释放线路，由模块上拉形成满足传感器阈值的高电平。
- TC264 数据手册把 P10.1 标为 VEXT 域 MP+ 引脚、P10.3 标为 VEXT 域 MP 引脚。只有核心板 VEXT 实际为 5 V 时，才允许保留模块的 5 V 上拉；VEXT 为 3.3 V 时必须改用 3.3 V 上拉或双向 IIC 电平转换。
- `P10.1/P10.3` 与 QSPI1、GPT12 TIM5 等复用功能互斥；当前 TIM2/TIM4 编码器不占用它们。

暂不实现 `0xD0/0xD1` 黑白滞回、`0xAD` 地址修改和广播复位；这些功能会增加校准或持久状态风险，应按明确需求单独移植。

`my_uart_init()` 只调用 `wireless_uart_init()`。底层负责 UART2、64 字节接收 FIFO、RX 回调、自动波特率和 RTS；应用层不得再次初始化 UART2 或改写回调。应用层把底层的 `0/非 0` 结果映射为 `MY_UART_STATUS_OK/MY_UART_STATUS_INIT_FAILED`，并记录初始化状态。

`my_printf()`：

- 未初始化时返回 `MY_UART_STATUS_NOT_INITIALIZED`；
- 使用默认 128 字节栈缓冲和 `vsnprintf()`，最多发送 127 字节；
- 超长文本会发送截断后的内容并返回 `MY_UART_STATUS_TRUNCATED`；
- 不自动追加 `\r\n`；
- 通过 `wireless_uart_send_buffer()` 保留 RTS 和最多 30 字节分段语义；
- 检查底层“未发送字节数”；非 0 时返回 `MY_UART_STATUS_SEND_TIMEOUT`，精确余量由 `my_uart_get_last_unsent_length()` 读取；
- 是阻塞接口，禁止在 ISR、闭环控制或高频采样路径调用。

`k230_app_service()` 每成功解码一个 `Flag=0x00` 的实际位置帧，就按合法性规则发布
`Ball_X` 快照，不在每帧调用 `my_printf()`。当前 K230 显示宽度为 800，
`k230_app` 只接受 `0..799` 的 `Ball_X`；超范围值不会写入位置快照、递增
`position_update_count` 或进入滚球控制。范围内的每个合法坐标都会直接写入位置
快照并递增 `position_update_count`，不进行相邻帧跳变过滤。需要诊断时，应在前台按低频
读取 `ball_control_snapshot_struct`，不能在 `ball_control_step_irq()` 中调用
阻塞式 `my_printf()`。

初始化状态和最近未发送长度显式放在 `cpu0_dsram`。`my_uart_is_ready()` 只反映底层最近一次初始化是否返回成功，不替代上板通信验证。

模块接线按信号方向理解：模块 TX → MCU `P10.6`/UART2 RX，模块 RX ← MCU `P10.5`/UART2 TX，RTS → `P10.2`。接口电平必须为 3.3 V。

### 7.2 底层核对结论

- `wireless_uart_init()` 调用 `uart_init()` 时先传 MCU TX `P10.5`，再传 MCU RX `P10.6`，参数顺序正确；宏名描述的是无线模块引脚方向，不能按宏名字面交换。
- `WIRELESS_UART_AUTO_BAUD_RATE == 1`。初始化等待由 5 ms、100 ms、20 ms 和 10 ms 固定延时组成，没有无限循环；模块必须连接 RTS 并支持自动波特率。
- `wireless_uart_send_buffer()` 在 RTS 高电平时最多等待约 100 ms，成功发送一个 30 字节块后重新计时。默认 127 字节文本最多分为 5 块，因此一次 `my_printf()` 在反复流控时可能阻塞数百毫秒。
- 当前底层自动波特率应答检查使用三个“不等于”条件的逻辑与，只有三个字节全部错误才判失败，不能证明应答严格等于 `A5 FF FF`。`libraries` 只读，本应用层无法读取其私有握手缓冲；初始化成功仍必须上板验证实际收发。
- RX 回调写入 64 字节 FIFO 时不向应用层报告溢出。本次不封装接收协议；后续若接收连续数据，必须先单独设计帧格式、超时、溢出统计和前台消费。

1. `my_task_tick_count` 加一；
2. 每拍调用 `imu_app_update()` 和 `gray_app_read()`；后者直接发布系数 `0.3` 一阶低通后的 `sample.error`；

6. 当 `question_app_is_track_running()` 为真时，每个 3 ms 拍先校验本拍灰度快照；所有题号均取消丢线停车。发车后尚无有效灰度时以目标角速度 0 按基础 PWM 直行；`error_num==0`、灰度状态异常或空样本只跳过本拍灰度外环，已经取得有效目标后继续使用最后一次目标，恢复有效黑线后每 12 ms 继续外环 PD；
7. Q2/Q4/Q5/Q6 每 6 ms 复用本拍 IMU 数据执行角速度内环 PD，计算 `pwm_curr`，再依次调用 `motor_set_A()`、`motor_set_B()`；IMU/零偏或 PID 异常时使用上次有效修正（初始为 0），电机接口错误只记录并在后续周期重试，均不写零或禁用控制；

### 9.3 Q0 零角速度环与 Q2 循迹串级 PD

`track_control` 使用两个互不共享历史状态的位置式 PID 实例，均固定 `ki=0`：

```text
Q0 零角速度调试：
校零后 Z 轴角速度
    → 6 ms 角速度 PD，target=0
    → pwm_curr
    → A = 0 - pwm_curr，B = 0 + pwm_curr

Q2/Q4/Q5/Q6 正常循迹：
灰度加权原始误差
    → gray_app 3 ms 一阶低通（新样本 0.3，历史结果 0.7）
    → sample.error（所有后续消费者共用）
    → 12 ms 外环 PD
    → 目标角速度（校零后原始 LSB）
    → 6 ms 角速度内环 PD
    → pwm_curr
    → A = pwm_base - pwm_curr，B = pwm_base + pwm_curr
```

`pid_step()` 的误差固定为 `target - actual`。`gray_app_read()` 已经把
`sample.error` 统一替换为 3 ms 低通结果，外环使用目标 `0`，直接把该滤波值
作为实际位置；`track_control` 不再维护第二份滤波状态。内环把外环输出作为
目标角速度，把所选轴的校零后原始 LSB 直接作为实际角速度。代码不再设置额外
方向参数，某一级方向错误时直接同时改变该级 `kp`、`kd` 的符号。电机混控固定
为 `A = pwm_base - pwm_curr`、`B = pwm_base + pwm_curr`。

参数组织参考 `myProjectV5.0` 的 `ControlPidConfig_t` 与 `.c` 参数表方式。PD 增益和陀螺仪轴在 `track_control.c` 顶部的只读参数表中调整；普通循迹基础 PWM 改由 `question_app.h` 按题号独立定义：

误差低通系数位于 `gray_app.h`，两个固定输出限幅位于 `track_control.h`：

```c
#define GRAY_APP_ERROR_FILTER_ALPHA          (0.3F)
#define TRACK_CONTROL_TARGET_GYRO_LIMIT_LSB  (4096.0F)
#define TRACK_CONTROL_PWM_CURR_LIMIT         (2000.0F)
#define TRACK_CONTROL_GYRO_DEBUG_PWM_BASE    (0)
```

低通系数必须处于 `(0, 1]`，当前 `0.3` 表示每个 3 ms 灰度采样时保留
`70%` 的上一拍滤波结果并引入 `30%` 的本拍原始误差。第一个输出限幅是
12 ms 外环目标角速度的绝对值上限，单位为校零后原始陀螺仪 LSB；第二个是
6 ms 内环输出 `pwm_curr` 的绝对值上限，单位为电机命令。两个限幅都必须
大于零。普通循迹每次使能时要求
`|pwm_base| + TRACK_CONTROL_PWM_CURR_LIMIT <= MOTOR_COMMAND_MAX` 和
`|TRACK_CONTROL_GYRO_DEBUG_PWM_BASE| + TRACK_CONTROL_PWM_CURR_LIMIT <= MOTOR_COMMAND_MAX`；
后一项由初始化阶段检查。

`gray_app_init()` 验证低通系数并清除滤波状态；`track_control_init()` 验证
两级 PD 参数、Q0 调试基础 PWM 和限幅后，把两组 PD 参数装入各自运行态实例。
普通 `track_control_enable(pwm_base)` 在启动时校验目标并立即把当前基础 PWM
设为该值；`track_control_enable_ramp(pwm_base_start, pwm_base_target,
ramp_inner_cycles)` 则显式保存起点、目标和总周期，第一次 6 ms 内环即输出起点，
不再等待灰度。Q0 的 `KEY_4` 路径调用
`track_control_enable_gyro_debug()`，强制目标角速度和基础 PWM 为 `0`，不等待
灰度样本；Q2 调用普通入口，Q4/Q5/Q6 调用 350 周期软启动入口。两种普通循迹入口
和 Q0 左右轮独立斜坡入口都没有丢线停车参数。各入口都会清除两个 PD 历史；
尚无有效灰度时使用目标角速度 0，仍按基础 PWM 推进软启动。一次两路电机输出
均成功后，完成周期才加一，并按
`start + round((target-start) * completed_before / (total-1))` 计算本拍基础
PWM。因此第一个成功周期精确采用起点，最后一个软启动周期精确采用目标；有符号
64 位中间量避免乘法溢出。灰度状态异常、空样本或 `error_num==0` 只跳过外环；
此前已有有效目标时继续使用该目标，否则保持目标角速度 0。`gray_app` 仍会在本拍
`error_num==0` 时清除滤波历史。IMU/零偏无效或 PID 数值错误时，内环沿用上次
有效 `pwm_curr`（初始为 0）继续下发基础值；电机接口错误不调用 `motor_stop_all()`，
保持控制使能并在下一周期重试。`question_app` 只同步这些诊断状态，不切换 `FAULT`
或关闭滚球/循迹另一环。诊断快照同时给出
当前 `pwm_base`、`pwm_base_ramp_start`、`pwm_base_target`、总周期和已完成周期。

当前灰度外环 `position_kp/kd=500/0`，角速度内环 `gyro_kp/kd=9/0`。Q2 的
题目级 `pwm_base` 发车为 `3200`，校零 Z 轴航向达到 `300 deg` 后切换为 `800`；

Q4/Q5/Q6 首周期请求各 `400`、稳态请求各 `1700`。
叠加 `TRACK_CONTROL_PWM_CURR_LIMIT=2000` 后仍未超过
`MOTOR_COMMAND_MAX=7000`。这些只证明静态配置和软启动公式已经接入，不证明
方向、速度、坡度或循迹增益适合实车。
参考 V5.0 的误差量纲、控制周期和微分定义与本工程不同，不能直接复制参数；
必须架空车轮确认方向，再上板整定各题基础 PWM、灰度外环和角速度内环。

当前参数表选择校零后的 Z 轴 LSB，但这不能证明 Z 轴就是实物偏航轴，也不能证明电机 A/B 分别是左/右轮。闭环使能前必须架空车轮，逐项验证灰度偏移、手动偏航和 `pwm_curr` 的方向；方向错误只修改相应 PD 的 `kp/kd` 符号。

### 9.4 Q3～Q6 滚球位置 PI—速度 PI 串级控制

`ball_control` 保留原有公开入口、题号调用链、中位叠加、机械软限位和 UART3
最新目标重试，并取消无新坐标自动关闭逻辑；它不再调用原来的“位置 PID + 并联实测速度
`Kv`”单环 PV 路径。当前闭环分成两级：

```text
位置 PI 外环：target_x - actual_x → target_velocity
速度 PI 内环：target_velocity - filtered_velocity → velocity PI pulse
可选加速度前馈：corrected_acc_y_lsb → acceleration FF pulse（Q3 输出限幅为 0；Q4/Q5 与 Q6 限幅为 100，且只在 350 周期车体缓启动尚未完成时允许）
原始控制量：velocity_PI_pulse + acceleration_FF_pulse
Q3 使用 +85/-100 pulse；Q4/Q5 与 Q6 共用 +80/-80 pulse 起滚补偿。近静止且 |位置误差|>15 px 时，将同方向小控制量提高到对应阈值
最终命令：center_pulse + compensated_controller_output → soft limit
```

3 ms 系统节拍按六分频形成 18 ms 速度内环时隙。只有
`position_update_count` 标识新 K230 坐标时才消费该坐标、更新速度并执行
一次位置式速度 PI；重复快照保持目标速度、两级积分和电机请求，不重复积分。
位置外环每三个已消费的新坐标更新一次，正常 56 Hz 数据流下名义周期为 54 ms。
首个启动后新坐标只建立速度历史并立即计算第一份目标速度；第二个新坐标才
产生第一份有效速度和第一份速度 PI 脉冲。Q3 当前将前馈输出限幅设为 `0`；
Q4/Q5 和 Q6 的前馈输出限幅为 `100`。`task` 每个 18 ms 滚球槽通过
`question_app_is_acceleration_feedforward_active_irq()` 查询车体斜坡进度；仅当
当前为 Q4/Q5/Q6 且 `completed_cycles < 350` 时计算并合成前馈，斜坡完成后
首个滚球槽把前馈目标和输出清零。Q0 `SOFT_START` 传入禁止，Q0 `ACCEL_FF`
专项调试在 `ball_control` 内强制允许。
3 ms 任务周期仍发布 IMU 最新的去零漂 Y 轴 raw LSB。

前馈直接使用 `imu_app.corrected_acc_y_lsb`。在
`IMU_APP_OFFSET_METHOD_AUTO_CALIBRATION` 下，启动标定会同时平均陀螺三轴
和加速度 X/Y；标定期间必须保持整车、滚球机构和最终安装姿态完全静止。
运行期不学习或更新零漂。前馈增益本身带符号，不另设方向宏。Q3 的前馈增益
和输出限幅均为 `0`；Q4/Q5 与 Q6 使用 `Kff=-1.3 pulse/LSB`，前馈输出
限幅为 `100`，只在各自车体缓启动窗口内产生受限前馈脉冲。

各题的静差都不再只靠继续放大速度积分解决，而是在近静止且误差超出保持窗口时，
直接按位置误差方向建立最小起滚倾角，即使速度 PI 暂时给出反向输出也会被纠正。
固定绝对脉冲测试得到：正脉冲使 `Ball_X` 减小，采用 `+85 pulse` 起滚；负脉冲
使 `Ball_X` 增大，采用 `-100 pulse` 起滚。补偿仅在
`|filtered_velocity|<=30 pixel/s` 且 `|位置误差|>15 px` 时生效，不改变 PI
积分状态，也不覆盖钢球运动中的反向制动命令。Q3 使用这组专用值；Q4/Q5 与
Q6 共用 `+80/-80 pulse`，Q6 的运行中心由停车态按键单独确定。

速度估计同时防止前台解析延迟和 56 Hz/18 ms 相位滑动造成的双帧速度尖峰：

```text
elapsed_control_s =
    elapsed_18_ms_slots_since_previous_consumed_position
camera_interval_s = position_update_delta / 56.0
velocity_observation_dt_s =
    max(elapsed_control_s, camera_interval_s)
raw_velocity_pixel_per_s =
    (actual_x - previous_fresh_actual_x) / velocity_observation_dt_s
filtered_velocity_pixel_per_s +=
    velocity_filter_alpha
    * (raw_velocity_pixel_per_s - filtered_velocity_pixel_per_s)
```

速度观察使用上述较大时间；速度 PI 的 `dt` 使用距上一次实际执行内环的
`elapsed_control_s`。若某个 18 ms 时隙没有新坐标，下一次执行内环时 `dt`
会自然变成 `36 ms`、`54 ms` 等实际间隔。

位置外环为带积分分离和积分限幅的位置式 PI，不直接输出步进脉冲。位置积分
只在当前题号参数表的 `position_integral_window_pixel` 内按两次实际外环执行
间隔累计；窗口外冻结已有积分但仍将其加入输出，避免进出窗口时目标速度突跳。
使能后的第一帧没有完整外环 `dt`，因此只计算 P：

```text
position_error =
    clamp(target_x - actual_x,
          -parameters.position_error_limit_pixel,
          +parameters.position_error_limit_pixel)
if abs(position_error) <= parameters.position_integral_window_pixel
        and outer_dt_s > 0:
    position_integral_velocity_pixel_per_s =
        clamp(previous_position_integral
              + parameters.position_outer_ki
                    * position_error * outer_dt_s,
              parameters.position_integral_min_velocity_pixel_per_s,
              parameters.position_integral_max_velocity_pixel_per_s)
else:
    position_integral_velocity_pixel_per_s =
        previous_position_integral
target_velocity_pixel_per_s =
    clamp(parameters.position_outer_kp * position_error
          + position_integral_velocity_pixel_per_s,
          -parameters.target_velocity_limit_pixel_per_s,
          +parameters.target_velocity_limit_pixel_per_s)
```

速度内环调用通用位置式 `pid_step()`，但其目标值和实际值都使用
`pixel/s`：

```text
velocity_error = target_velocity_pixel_per_s
                 - filtered_velocity_pixel_per_s
velocity_integral_output_pulse =
    clamp(previous_integral_output_pulse
          + parameters.velocity_inner_ki
                * velocity_error * inner_dt_s,
          parameters.velocity_integral_min_pulse,
          parameters.velocity_integral_max_pulse)
velocity_pi_output_pulse =
    clamp(parameters.velocity_inner_kp * velocity_error
          + velocity_integral_output_pulse,
          min_pulse - center_pulse
              + parameters.acceleration_feedforward_output_limit_pulse,
          max_pulse - center_pulse
              - parameters.acceleration_feedforward_output_limit_pulse)
acceleration_feedforward_pulse =
    slew_limit(
        gain_pulse_per_lsb
            * deadband_and_clamp(corrected_acc_y_lsb),
        previous_acceleration_feedforward_pulse)
controller_output_pulse =
    velocity_pi_output_pulse + acceleration_feedforward_pulse
absolute_pulse =
    clamp(center_pulse + controller_output_pulse,
          min_pulse,
          max_pulse)
```

位置外环和速度内环都复用通用 `pid_step()` 的条件抗饱和：候选积分若把
饱和输出继续推向同一方向，该次积分会冻结或截断；反向积分仍可释放饱和。
`controller_output_pulse` 是本拍绝对位置偏移，不会累加到上一拍脉冲。

串级结构最初由旧单环 PV 做代数映射，但参数现在按题号分开：Q3 使用用户
继续整定后的专用参数；Q4/Q5 使用共同参数，Q6 保留独立参数。Q3 关闭加速度
前馈，Q4/Q5 与 Q6 的表内前馈只在车体缓启动阶段由题目层允许；Q3 使用 `+85/-100 pulse`，
Q4/Q5 与 Q6 共用 `+80/-80 pulse` 起滚补偿。
位置积分用于修正目标附近的残余静差，不改变原单环 PV 已停止调用的事实；
这些数值仍不证明机构方向、滤波延迟或实物稳定性。

两级 PI；Q6 会在装载参数时复制当前 RAM 运行中心，`target_x` 不参与中心选择。

触发第一拍；使能时清空位置 PI、速度 PI、速度历史、外环分频和诊断输出。
非法参数集返回 `BALL_CONTROL_STATUS_INVALID_CONFIG`，不会沿用上一次参数。
`target_velocity_pixel_per_s`、`position_integral_velocity_pixel_per_s`、
`velocity_error_pixel_per_s`、`filtered_velocity_pixel_per_s` 分别记录外环
输出、位置 I 输出、内环误差和滤波速度；
`integral_output_pulse` 记录内环 I，`pid_output_pulse` 记录限幅后的速度 PI
总输出，`controller_output_pulse` 记录速度 PI、可选加速度前馈以及起滚补偿后的
最终绝对位置偏移。为减少已有快照接口
破坏，字段 `velocity_output_pulse` 保留原名，但现记录速度 PI 的未限幅 P 项。
`control_update_count` 只统计实际执行的速度 PI，`outer_update_count` 统计位置
外环更新。

`ball_control_set_target()` 只接受已使能控制器。若已经有有效实际位置，它以
`dt=0` 立即重算新目标对应的位置 P，并保留位置 I、速度 I、速度历史、当前使能
状态和最新电机请求；随后从零重新累计 54 ms 外环间隔。该接口不发送串口、不
等待，也不调用 `ball_control_enable()`，因此 Q3 切换目标不会重启控制器。

没有新位置时，`ball_control_step_irq(feedforward_allowed)` 不推进位置/速度 PI，也不清空目标速度、
速度历史、两级 PI 积分或输出；控制器保持使能，最新绝对位置继续有效并按需重试，
加速度前馈仅在 `feedforward_allowed` 为真时按 18 ms 路径更新，否则立即清零。后续新位置到达后，速度观察按实际累计间隔
恢复，串级闭环直接继续运行，不再存在 `POSITION_STALE` 自动回中或关闭路径。

每次只保留最新绝对目标。若 UART3 FIFO 忙，`TX_BUSY` 不进入故障，后续
18 ms 时隙重试届时最新目标；旧目标不排队。PI 数值错误或其它步进发送错误
会清空串级状态并锁存故障。由于驱动链无回包，这些状态只能证明本地计算和
发送动作，不能证明驱动器在线或已到位。

上电只执行 `Step_Motor_Init()` 的“初始化 UART3 → 等待 500 ms → 使能 → 停止”
序列。工程只保留固定最近点回零触发，不提供写当前位置、设置零点、修改回零配置、中止回零或原始帧发送入口。进入 Q0 停车页后，`KEY_2`
只调用 `Trigger_Return()` 触发回到驱动器外部既有机械零点，并在帧成功入 FIFO 后重置本地 KEY3 测试状态。Q6 `IDLE` 的 `KEY_2/KEY_3` 只发送新的绝对位置并在发送成功后更新 RAM 运行中心；它们不调用任何回零或写零接口。Q0 回零、Q0 KEY3 和 Q6 中心位置命令遇到
`TX_BUSY` 都不自动重试。用户
仍须确认机械方向、驱动器外部既有机械零点，并在断开机构或电机动力时验证
`[-400,+400]` 行程。当前串级增益、位置积分窗口、两级积分限幅、滤波、速度
限幅和误差限幅均是待上板整定值，不能视为完成实机闭环验证。

Q0 固定脉冲机构测试不调用 `ball_control`，也不运行位置/速度 PI。每次成功的
`KEY_3` 命令建立一个新试次并立即输出首行，随后前台每 `150 ms` 输出：

```text
PT,ID,EL,RQ,AP,MS,PV,BX,DX,PU,DU
```

`ID` 为试次号，`EL` 为命令后的毫秒数，`RQ/AP` 为请求和本地发送层接受的绝对
脉冲，`MS` 为步进发送状态，`PV/BX` 为 K230 位置有效位和当前坐标，`DX` 为
相对本试次首坐标的变化，`PU/DU` 为绝对位置更新计数和本试次增量。`AP=RQ`、
`MS=OK` 仍不能证明驱动器到位；K230 丢检后若重复旧坐标，`PU/DU` 也可能继续
增长，因此必须同步人工记录电机轴、连杆、水管和钢球的实际动作。

`question_app_process_k230_touch()`，随后才判断题目状态。非题目态扫描按键并

RUN 画面。IMU 的三轴陀螺仪、X/Y 轴加速度计和灰度均由 ISR 每 3 ms 采样，
菜单每 150 ms 复制
最新快照并刷新。上电 Q0 收到位置后的前六行示例为：

```text
GRAY:11111111 E:+0.00 N:0
```

`raw - offset`，不换算为 `m/s^2`、不维护 Z 轴加速度，也不在 `imu_app`
内低通。自动标定同时平均陀螺三轴和加速度 X/Y，并各打印一行可复制的
raw-LSB 零漂；固定模式使用对应五个固定宏。IMU 硬件 SPI、灰度 Soft IIC、
权重误差计算和灰度误差一阶低通都位于每拍执行的 3 ms 采样层；Q0 当前
`SOFT_START` 读取 K230 位置并推进滚球闭环，CH2 触发后再运行两段车体斜坡；
Q2 的 6/12 ms 控制处理读取本拍 IMU/灰度快照；Q3～Q6 的 18 ms 控制时隙读取
K230 前台快照，其中 Q3 关闭前馈，Q4/Q5 和 Q6 只在车体缓启动阶段允许前馈，并使用近静止起滚补偿。当前
编码器只用于非题目态菜单显示，所以仍在主循环读取。
后续速度 PID 若使用编码器，读取/清零和 PID 必须一起移入控制 ISR，菜单改为
复制 ISR 快照。K230 成帧、ADC 均值采集、按键 GPIO 扫描、格式化和写屏都在
主循环；题目态继续 K230 成帧与电池 ADC，但不执行按键、格式化或写屏。
运行期前台不再 Ping 灰度传感器，避免与控制 ISR 争用 Soft IIC。

## 10. K230 双向通信与步进电机单向发送

线协议、字节字段和滚球闭环接口契约以
[`K230_TC264_步进电机串口通信协议.md`](./K230_TC264_步进电机串口通信协议.md)
为专项说明；本节记录工程资源、调用方式和验证边界。

### 10.1 方向与软件边界

| 项目 | K230 双向链路 | 步进电机发送链路 |
|---|---|---|
| 数据方向 | K230 ↔ TC264 | TC264 → 步进驱动器 |
| TC264 串口 | UART1 | UART3 |
| 实际信号线 | `P02.2` → K230 RX；K230 TX → `P02.3` | `P15.6` → 驱动器 RX |
| 不接线引脚 | 无；TX/RX 都使用 | `P15.7`；仅作 `uart_init()` RX 占位 |
| 默认格式 | 115200 bit/s，8N1，无流控 | 115200 bit/s，8N1，无流控 |
| 中断/发送 | RX 中断优先级 14；TX 前台阻塞发送，TX 中断关闭 | RX/TX 中断均关闭；固定最近点回零、实时速度和绝对位置固定帧使用非阻塞 FIFO 写入；无写零或回零配置接口 |
| 应用模块 | `k230_uart.h/.c`、`k230_app.h/.c` | `stepper_uart.h/.c`、`step_motor.h/.c` |

两路串口底层没有跨模块包装层，也没有直接物理连接：`k230_app` 只封装 K230
前台成帧和最新实际位置快照；步进模块只负责向驱动器发命令，二者分别初始化，
驱动模块互不调用。应用层 `ball_control` 只读取前者快照并调用后者的绝对位置
接口。

K230 链路的 TC264 UART1 两个引脚都必须接线：`P02.2` 接 K230 UART2
`GPIO12`/RX，`P02.3` 接 K230 UART2 `GPIO11`/TX。只有步进 UART3 是单向
链路：逐飞 `uart_init()` 必须同时传入 TX/RX 引脚枚举，因此 MCU 内仍配置
`P15.7`，但该引脚不接驱动器 TX，也没有接收软件路径。

### 10.2 K230 与 TC264 双向收发

TC264 向 K230 发送固定 4 字节命令：

```text
20 Data1 Data2 30
```

K230 向 TC264 发送固定 5 字节数据：

```text
40 Flag Data1 Data2 50
```

`Flag = 0x00` 时，数据为：

```text
40 00 Ball_X_H Ball_X_L 50
```

`Flag = 0x0A` 时，数据为：

```text
40 0A Touch_X_H Touch_X_L 50
```

触摸标志字节必须是 `0x0A`，不是 `0xA0`；`0xA0` 属于保留标志，接收端会
消费完整帧但不会更新 `Touch_X` 或 Q6 目标。

钢球实际位置和触摸 X 都使用无符号 16 位整数，高八位先发。K230 每次新的
屏幕点击把同一 `0x0A` 帧连续发送 3 次，不发送触摸 Y。
`k230_uart_decode_ball_x()` 只接受 `0x00`，
`k230_uart_decode_touch_x()` 只接受 `0x0A`；`k230_app` 为两类数据维护独立
有效位、数值和更新计数，因此触摸帧不会覆盖 `Ball_X`。所有题号都会推进已见
触摸计数，只有当前 Q6 采用新的 `Touch_X`；同值三连帧不会重复改变目标。
双向协议帧都没有长度、序号或 CRC；其它 `Flag` 值保留。
TC264 使用 `k230_uart_write()` 发送任意缓冲区，或使用
`k230_uart_send_command(data_1, data_2)` 发送上述 4 字节命令。发送路径会
等待 UART TX FIFO，只允许在 CPU0 前台调用，不能放进 3 ms 控制 ISR。

当前 CPU0 前台接收调用链：

```c
my_menu_init();          /* 内部 k230_app_init()，开启 UART1 RX。 */
my_menu_proc();          /* 先收帧，再处理 Q6 触摸；所有题目状态都执行。 */
```

UART1 ISR 每次只搬运一个字节到 128 字节环形缓冲，固定帧解析留在 CPU0
前台。缓冲区可保存 127 字节，即 25 个完整 5 字节帧；一次点击的三连发占
15 字节。`k230_app_service()` 每次最多处理 27 个完整帧并分别保存最新实际
位置、触摸位置快照，可用 `k230_uart_get_rx_overflow_count()` 监测溢出。

### 10.3 TC264 只向步进驱动器发送

单电机上层固定使用地址 `0x01`，常用帧如下：

```text
使能：01 F3 AB 01 00 6B
速度：01 F6 Dir Speed_H Speed_L Acc 00 6B
位置：01 FD Dir 01 F4 00 Pulse_BE32 01 00 6B
停止：01 FE 98 00 6B
最近点回零：01 9A 00 00 6B
```

初始化和实时控制分别调用：

```c
#include "code/step_motor.h"

/* PIT 启动前、CPU0 前台。 */
(void)Step_Motor_Init();

/* Q0 停车态 KEY2；只触发回到驱动器既有机械零点。 */
(void)Trigger_Return();

/* 实时控制 ISR 中；正数 CW，负数 CCW。当前滚球业务不使用速度模式。 */
(void)Step_Motor_Set_Speed(signed_speed);

/* 18 ms 速度 PI 有效拍；传入已经限幅的最终绝对目标脉冲。 */
(void)Step_Motor_Set_Position(signed_pulse_count);
```

`Step_Motor_Init()` 在前台依次初始化 UART3、等待驱动器上电 500 ms、发送使能、等待 10 ms，再发送停止命令；只有停止帧成功交给本地发送层后才发布初始化完成。`Trigger_Return()` 只非阻塞发送固定最近点回零帧，触发驱动器回到外部既有机械零点。工程不公开或实现当前位置清零、设置零点、修改回零配置、中止回零及原始帧发送入口。

`Step_Motor_Set_Speed(0)` 发送零速度 `F6` 帧，不等于 `FE` 停止。当前 `step_motor` 没有公开运行期停止接口；滚球坐标暂时失新时保持使能、串级状态和最新绝对位置请求，不再自动清空 PID 或请求中位。只有显式禁用、PID 数值错误或非 `TX_BUSY` 的本地步进接口错误仍进入原有安全中位/故障处理。

初始化、使能和停止走阻塞式前台接口；`Trigger_Return()`、实时 `F6`
速度和 `FD` 绝对位置接口只在 UART3 TX FIFO 为空时写入完整固定帧，忙时立即
返回 `TX_BUSY`，均不排队。Q0 `KEY_2` 的回零帧失败时由用户再次短按；速度/位置由控制 ISR 后续拍直接重试最新目标。

`Step_Motor_Set_Position()` 固定发送绝对位置 `FD` 帧：正负号在内部转换为
CW/CCW，绝对值转换为脉冲数，速度和加速度分别由
`STEP_MOTOR_POSITION_SPEED_RPM`、`STEP_MOTOR_POSITION_ACCELERATION` 配置。
当前 X42S 为 Emm 固件且已设置 `S_Vel_IS=Enable`，所以源码把速度字段
`500` 原样发出时，驱动器实际按 `50.0 RPM` 运行；加速度档为 `0`。按手册
V1.0.5 的 Emm `F6/FD` 帧定义，线上速度字段范围是 `0..3000`，源码只做该
字段边界校验，不在 TC264 内乘 10 或除 10。
该接口不等待 10 ms 命令间隔，也不等待线路发送完成，可在实时控制 ISR
调用。115200 bit/s、8N1 下，5 字节回零帧在线约 0.43 ms、8 字节速度帧在线约
0.69 ms、13 字节位置帧约 1.13 ms，三者都能一次装入 16 字节 FIFO；但命令锁、其它发送或调用时刻仍
可能导致 `TX_BUSY`。回零触发不自动重试；速度/位置控制器必须在后续控制拍直接重试最新目标。
传入值是以驱动器外部既有机械零点为基准的最终绝对坐标，不是摄像头误差或本次增量；调用方
必须按连杆机械行程把目标钳位在固定绝对坐标范围内。Q6 可以维护 RAM 数学中心，
但不能建立、覆盖或修改驱动器机械零点。

UART3 不接驱动器 TX、不打开 RX 中断，也没有 RX 缓冲、回包解析、遥测读取
或 ACK 接口。所有 `OK` 只表示本地参数检查和发送动作成功，不能证明驱动器
在线、已使能、已经完成回零或已经达到目标速度/位置。

### 11.2 电机接口与安全状态

`motor_init()` 先把四个方向输出锁存为低电平并配置为 GPIO，再以零占空比

电机命令保留 MSPM0 参考工程的 `-7000..7000` 数值范围，并按原参考周期
8000 换算到逐飞的 `PWM_DUTY_MAX=10000`；因此 `7000` 对应 87.5% 占空比。
超范围输入在驱动内钳位。正命令为 IN1 高、IN2 低，负命令相反。

驱动板内部芯片真值表；在未取得准确型号和手册前不对机械行为作保证。

整数毫伏换算带半分母舍入：

```text
Vbat_mV = ADC × 3300 × (200000 + 20000) / (4095 × 20000)
         = ADC × 3300 × 11 / 4095
```

例如 `ADC=1354` 时显示 `BAT:12.002V ADC:1354`。ADC 满量程对应理论 36.300 V，不代表主板允许该输入；V2.6.2.1 原理图标注的电池输入范围仍为 7.2～24 V。

`my_menu_init()` 调用 `my_battery_init()`；`my_menu_proc()` 每 9 ms 消费一次电池采样事件并更新缓存，每 150 ms 显示一次第 6 行。ADC 采集和格式化都在 CPU0 前台完成，ISR 不访问 VADC。

逐飞 `adc_init()` 和 `adc_mean_filter_convert()` 没有硬件错误返回；后者等待结果有效标志。因此 `my_battery_is_ready()` 只表示初始化调用和首次采集已执行，不证明参考电压、分压网络或实物读数正确。若板型不同，应先修改 `my_battery.h` 中的参考电压和电阻参数，再用万用表校准。
