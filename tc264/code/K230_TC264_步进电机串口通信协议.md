# K230、TC264 与步进驱动器串口协议

两条链路均为 115200 bit/s、8N1、无硬件流控。K230 与 TC264 使用 3.3 V TTL、共地；步进驱动器须预先配置相同的串口参数并与 TC264 共地。

## K230 ↔ TC264

K230 UART2 TX（GPIO11）接 TC264 UART1 RX（P02.3）；TC264 UART1 TX（P02.2）接 K230 UART2 RX（GPIO12）。

K230 每处理一帧图像就发送一个 5 字节帧：`40 Flag X_H X_L 50`。下表字节均为十六进制，X 为 16 位无符号大端数，TC264 接受的显示坐标为 `0..799`。

| Flag | K230 发送条件 | TC264 行为 |
| --- | --- | --- |
| `00` | 已识别过钢球；当前帧未检出时，重复最近一次有效 X | 更新钢球位置快照；重复值也计为一次更新 |
| `01` | 尚无有效识别，X 为零 | 忽略，不把零当作钢球位置 |
| `0A` | 新按下屏幕时，额外连续发送三份相同的触摸 X 帧 | 独立更新触摸快照；只有 Q6 停车待发时采用新触摸目标 |

例如钢球在 X=275 时发送 `40 00 01 13 50`；点击 X=400 时发送三份 `40 0A 01 90 50`。未知标志和越界坐标不更新快照。帧无校验和；载荷中的 `40` 或 `50` 是普通数据。包尾错误时丢弃该帧；若错误包尾为 `40`，直接作为下一帧的包头。

反向接口 `k230_uart_send_command(data_1, data_2)` 可发送 4 字节帧 `20 Data1 Data2 30`。当前 [K230 脚本](../../k230/main.py) 不解析该命令，也不返回应答。TC264 端见 [帧解析](k230_uart.c) 和 [坐标快照](k230_app.h)。

## TC264 → 步进驱动器

TC264 UART3 TX（P15.6）接驱动器 RX。P15.7 仅供串口初始化，外部不接；驱动器 TX 不接。下表为[单电机接口](step_motor.h)使用的 Emm_V5 帧，地址为 `01`，帧尾固定为 `6B`。

| 操作 | 线上字节（十六进制） |
| --- | --- |
| 使能 | `01 F3 AB 01 00 6B` |
| 停止 | `01 FE 98 00 6B` |
| 触发回到既有机械零点 | `01 9A 00 00 6B` |
| 速度 | `01 F6 Dir Speed_H Speed_L Acc 00 6B` |
| 绝对位置 | `01 FD Dir 01 F4 00 Pulse_BE32 01 00 6B` |

`Dir=00` 为正向（CW），`01` 为反向（CCW）。速度和脉冲字段均发送绝对值，高字节在前；`Pulse_BE32` 占 4 字节，以驱动器既有机械零点为基准。速度原始字段范围为 `0..3000`；使用 `S_Vel_IS=Enable` 时，位置帧的速度字段 `01 F4`（十进制 500）表示 50.0 RPM。速度设为零仍是 `F6` 帧。

初始化依次发送使能和停止，不自动回零。运行时的回零、速度和位置请求若返回 `STEPPER_UART_STATUS_TX_BUSY`，表示本次请求未提交；成功只表示本地已接受发送。链路不接收 ACK、位置或回零完成反馈。使用绝对位置前需按实物确认机械零点、方向与行程。发送实现见 [step_motor.c](step_motor.c) 和 [stepper_uart.c](stepper_uart.c)。
