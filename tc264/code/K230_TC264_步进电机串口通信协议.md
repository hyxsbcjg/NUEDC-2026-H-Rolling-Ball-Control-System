# K230、TC264 与步进电机串口通信协议

> 文档状态：当前通信基线  
> 适用对象：K230、TC264D 和使用 Emm_V5 串口协议的步进电机驱动器  
> 源码基线：K230 `传统CV/main.py`；TC264 `k230_uart`、`k230_app`、`ball_control`、`question_app`、`menu`、`stepper_uart`、`step_motor`、`pid`、`task` 和当前 CPU0 入口  
> 触摸扩展状态：K230 已实现 `Flag=0x0A` 三连发；TC264 已实现独立解析，并且只允许 Q6 `IDLE` 采用为目标  
> 规范用语：“必须”表示固定约束，“建议”表示可按实物测试调整

## 1. 范围与通信关系

本协议定义三条数据链路：

1. `TC264 → K230`：发送两字节命令。
2. `K230 → TC264`：发送钢球实际 X 位置，或发送屏幕点击得到的触摸 X
   坐标；标志位 `0x00` 表示钢球位置，`0x0A` 表示触摸位置。
3. `TC264 → 步进电机驱动器`：只发送使能、速度、绝对位置、停止，以及 Q0 `KEY_2` 使用的固定最近点回零触发命令；工程不提供任何写零、设置零点或修改回零配置的入口。

K230 与 TC264 双向通信。TC264 与步进电机驱动器只使用单向控制，不处理驱动器回包。两条底层链路独立初始化，驱动模块互不调用；应用层 `ball_control` 读取实际 `Ball_X` 快照并调用步进绝对位置接口，`question_app` 独立读取 `Touch_X` 快照并按题号决定是否采用。

本文同时记录现有模块边界和接入状态。K230 现在可以用 `Flag=0x0A`
发送用户点击得到的触摸 X 坐标。TC264 把 `Ball_X` 与 `Touch_X` 分开缓存；
只有当前题号为 Q6 且处于 `IDLE` 时，`question_app` 才采用新的 `Touch_X`。Q3 先以 546 像素为目标，实际
位置进入闭区间 `[526,546]` 后单向切换并持续稳定在 234 像素；Q4/Q5 固定
为 396 像素；Q6 没有本地固定目标，停车态合法 `Touch_X` 优先，未设置时由
`KEY_4` 锁存发车前最新有效 `Ball_X`，两者均无效才拒绝启动。Q6 停车态
`KEY_2=-20 pulse`、`KEY_3=+20 pulse` 调整 RAM 绝对中心；
中心与 Target 数值无关，成功发送绝对位置后才提交。
这些默认参数统一记录在
`question_app.c:question_app_ball_parameter_table`。滚球串级增益、速度滤波和
各类限幅在 `ball_control.c` 中按题号拆成三张表：
`ball_control_q3_parameter_table` 只给 Q3，
`ball_control_q4_q5_parameter_table` 只给 Q4/Q5，
`ball_control_q6_parameter_table` 只给 Q6。`question_app` 每次使能滚球时
显式传入参数集，不继承上一次题号。Q3 当前位置外环
`Kp/Ki=+1.65/+10.0`、积分窗口 `±82 px`、位置 I 输出限幅
`±70 pixel/s`，速度内环 `Kp/Ki=-0.8/-0.08`；Q4/Q5 当前使用位置外环
`+0.92/0.0`、积分窗口 `±60 px`、位置 I 输出限幅 `±30 pixel/s`、速度内环
`-0.92/0.0`，速度 I 输出限幅 `±60 pulse`；Q6 独立使用位置 `+0.92/0.0`、速度
`-0.82/0.0`，速度 I 输出限幅同为 `±60 pulse`。Q3 的加速度前馈输出限幅为 `0`；
Q4/Q5 和 Q6 的输出限幅为 `100`，前馈增益均为 `-1.3 pulse/LSB`、死区均为
`52 LSB`，但题目层只在 350 周期车体缓启动尚未完成时允许前馈。Q3 使用专用起滚补偿，Q4/Q5
与 Q6 共用 `+80/-80 pulse`；近静止且误差超出 `±15 px` 时按位置误差
方向施加对应最小起滚补偿，即使 PI 暂时给出反向输出也会纠正；
静止速度阈值均为 `±30 pixel/s`。三套表当前均使用目标速度
限幅 `±1000 pixel/s`、速度滤波权重 `0.25`、位置误差限幅 `±10000 px`；
Q3 速度 I 输出限幅为 `[-80,+80] pulse`。56 Hz 帧率、
18/54 ms 周期、Q3/Q4/Q5 驱动器绝对中位 `0`、Q6 按键步长和固定绝对软限位
`[-400,+400]` 记录在 `ball_control.h`。Q6 运行时装载停车态提交的 RAM 中心，
再与控制器输出相加；该数学中心不写机械零点，原单环 PV 调用已停止。
`ball_control_set_target()` 仍用于 Q3 的题目级目标切换。Q6 发车后不再接受
新的触摸目标，已锁存的 `target_x` 在本次运行中保持不变。Q6 像素标定、连杆
脉冲换算和实机整定仍待完成。Q4/Q5/Q6 发车后都会同时启动车体循迹；三题不在
TC264 内部计时，不判 B/A 完成，也不做正常完赛自动停车。

本项目固定采用以下规则：

- `Flag=0x00` 的位置帧只包含钢球实际 X 坐标。
- `Flag=0x0A` 的触摸帧只包含点击位置的 X 坐标，不发送点击 Y 坐标。
- 触摸标志字节必须是 `0x0A`，不是 `0xA0`；`0xA0` 属于保留标志，不会更新触摸目标。
- `Flag=0x0A` 只在当前题号为 Q6 且处于 `IDLE` 时改变目标；Q0～Q5 以及 Q6 运行态只消费更新，不留作后来切到 Q6 时使用。
- K230 与 TC264 的自定义帧使用固定长度、固定包头和固定包尾。
- 步进电机命令使用固定长度和固定帧尾 `0x6B`。
- 多字节整数必须先发送高八位，再发送低八位。
- K230 与 TC264 的帧不增加长度、序号、CRC 或校验和。
- TC264 的 UART1 RX 中断只收取单字节；前台负责成帧和发送。
- `my_menu_proc()` 在发车态和停车态都先调用 `k230_app_service()`，随后调用 `question_app_process_k230_touch()`；题目状态不关闭 UART1 RX。

## 2. 串口配置

### 2.1 K230 与 TC264

| 项目 | 配置 |
| --- | --- |
| K230 串口 | UART2 |
| K230 TX | `GPIO11`，连接 TC264 `P02.3`/UART1 RX |
| K230 RX | `GPIO12`，连接 TC264 `P02.2`/UART1 TX |
| TC264 串口 | UART1 |
| 波特率 | 115200 bit/s |
| 数据格式 | 8 数据位、无校验、1 停止位 |
| 硬件流控 | 无 |
| TC264 TX | `P02.2`，连接 K230 `GPIO12`/UART2 RX |
| TC264 RX | `P02.3`，连接 K230 `GPIO11`/UART2 TX |

两端必须共地，TX 与 RX 交叉连接，串口信号电平必须兼容。

K230 使用 UART2，不开串口中断。K230 `传统CV/main.py` 把 GPIO11/12 复用
为 `UART2_TXD/UART2_RXD`，并使用普通 `uart.write()` 发送触摸帧，本轮不
增加 TC264 命令接收逻辑。触摸帧三连发使用一次 15 字节 `uart.write()`，
三个 5 字节帧之间不插入人为延时。TC264 只开启 UART1 RX 中断；UART1 TX
中断保持关闭。

K230 和 TC264 必须都配置为 115200 bit/s。本协议不自动检测或协商波特率。

### 2.2 TC264 与步进电机驱动器

| 项目 | 配置 |
| --- | --- |
| TC264 串口 | UART3 |
| 波特率 | 115200 bit/s |
| 数据格式 | 8 数据位、无校验、1 停止位 |
| 硬件流控 | 无 |
| TC264 TX | `P15.6`，连接驱动器 RX |
| TC264 RX | `P15.7`，逐飞 `uart_init()` 需要，协议不使用 |
| 通信方向 | TC264 单向发送 |

TC264 与驱动器必须共地。驱动器 TX 不接。UART3 RX 和 TX 中断均保持关闭；初始化和配置使用阻塞发送，回零、周期速度和位置固定帧使用非阻塞空 FIFO 写入。

驱动器端也必须预先设置为 115200 bit/s。修改 `STEPPER_UART_BAUD_RATE` 只会改变 TC264，不能自动修改或识别驱动器参数；两端不一致时，本单向链路也没有回包可用于报错。

TC264 UART1 由 K230 链路独占，K230 端对应 UART2；TC264 UART3 由步进电机
驱动器独占。程序不得在各自芯片上重复初始化这些 UART。

## 3. TC264 向 K230 发送命令

命令帧固定为 4 字节：

| 偏移 | 字段 | 内容 |
| ---: | --- | --- |
| 0 | 包头 | `0x20` |
| 1 | 数据 1 | `Data1` |
| 2 | 数据 2 | `Data2` |
| 3 | 包尾 | `0x30` |

帧格式：

```text
0x20 | Data1 | Data2 | 0x30
```

TC264 使用现有接口发送：

```c
k230_uart_send_command(data_1, data_2);
```

`Data1` 和 `Data2` 的命令含义由 K230 程序另行定义，本协议只固定传输格式。

## 4. K230 向 TC264 发送数据

水管只有一个运动方向，因此 K230 上行数据只使用 X 坐标：
`Flag=0x00` 上传钢球实际 X，`Flag=0x0A` 上传屏幕点击 X。TC264 只在当前
题号为 Q6 时把最新触摸 X 用作目标；其它题号的目标规则保持不变。

K230 上行帧固定为 5 字节：

| 偏移 | 字段 | 内容 |
| ---: | --- | --- |
| 0 | 包头 | `0x40` |
| 1 | 标志位 | `Flag` |
| 2 | 数据 1 | 由 `Flag` 决定；16 位 X 坐标的高八位 |
| 3 | 数据 2 | 由 `Flag` 决定；16 位 X 坐标的低八位 |
| 4 | 包尾 | `0x50` |

通用帧格式：

```text
0x40 | Flag | Data1 | Data2 | 0x50
```

标志位定义：

| `Flag` | 数据含义 |
| --- | --- |
| `0x00` | `Data1、Data2` 表示有效的钢球实际 X 位置 |
| `0x0A` | `Data1、Data2` 表示一次屏幕点击的触摸 X 坐标；K230 连续发送 3 帧；TC264 独立更新触摸快照 |
| 其它值 | 保留；TC264 消费该帧，但不更新任何坐标快照 |

注意：触摸标志位是 `0x0A`，不是 `0xA0`。

当 `Flag = 0x00` 时，帧格式为：

```text
0x40 | 0x00 | Ball_X_H | Ball_X_L | 0x50
```

当 `Flag = 0x0A` 时，单帧格式为：

```text
0x40 | 0x0A | Touch_X_H | Touch_X_L | 0x50
```

两种帧都不包含 Y 坐标、长度、序号或校验码。接收端只检查包头、固定长度和
包尾。

### 4.1 K230 拆分实际位置

钢球像素 X 使用无符号 16 位整数，高八位先发送：

```python
frame = bytes([
    0x40,
    0x00,
    (ball_x >> 8) & 0xFF,
    ball_x & 0xFF,
    0x50
])

uart.write(frame)
```

K230 一次写入完整帧。UART 仍按顺序逐字节发送，不需要在字节之间增加延时。

### 4.2 K230 发送触摸 X 坐标

屏幕显示坐标为 `(Touch_X, Touch_Y)`，但串口只发送与滚球运动方向对应的
`Touch_X`。每次新的按下事件只触发一次发送；手指保持按下不会重复触发。
`Touch_X` 按无符号 16 位整数拆成高、低字节，同一帧连续发送 3 次：

```python
frame = bytes([
    0x40,
    0x0A,
    (touch_x >> 8) & 0xFF,
    touch_x & 0xFF,
    0x50
])

written = uart.write(frame * 3)
```

三个副本组成一个连续 15 字节突发，不在帧间调用延时。115200 bit/s、8N1
下，该突发在线时间约为 `15 × 10 / 115200 ≈ 1.30 ms`。

例如点击坐标为 `(400, 240)`：

```text
Touch_X = 400 = 0x0190

单帧：40 0A 01 90 50
三连发：40 0A 01 90 50 40 0A 01 90 50 40 0A 01 90 50
```

K230 必须检查 `uart.write()` 的返回值是否为 `15`。当前 K230 程序短写时输出
错误并保留视觉主循环，但不会把不完整突发宣称为发送成功。

### 4.3 TC264 合并实际位置

`k230_uart_read_frame()` 提交的结构体不包含包头和包尾。`frame.flag` 等于
`0x00` 时，`k230_uart_decode_ball_x()` 按高字节在前恢复一个 16 位位置：

```c
ball_x = ((uint16)frame.data[0] << 8U) | (uint16)frame.data[1];
```

例如：

```text
Ball_X = 275 = 0x0113

发送帧：40 00 01 13 50
```

当前 K230 显示宽度为 800，TC264 应用层只接受 `0..799` 的 `Ball_X` 和
`Touch_X`。超范围 `Ball_X` 不会写入实际位置快照或递增
`position_update_count`；超范围 `Touch_X` 不会写入触摸快照、递增
`touch_update_count` 或成为 Q6 目标。
范围内的每个合法 `Ball_X` 都直接写入 `k230_app_snapshot.ball_x` 并递增
`position_update_count`，不进行相邻帧跳变过滤。

## 5. TC264 上行帧接收规则

TC264 按以下步骤拼接 K230 上行帧：

1. 等待包头 `0x40`。
2. 收到包头后，再接收 4 个字节。
3. 收满 5 个字节后，检查最后一字节是否为 `0x50`。
4. 包尾正确时提交完整帧；包尾错误时累计帧错误并重新同步。若错误包尾本身等于 `0x40`，则直接把它复用为下一帧包头。

接收固定长度帧时，载荷中的 `0x40` 或 `0x50` 只作为普通数据。接收端不得在帧未收满时重新判断包头或包尾。

UART1 接收中断每次读取一个字节并写入环形缓冲区。CPU0 前台从环形缓冲区
取出字节并完成成帧；中断内不解析协议。当前上层由 `k230_app` 独占完整帧
消费权，并分别发布最新实际 `Ball_X` 与点击 `Touch_X` 快照。两类快照各有
独立的 `valid` 和 `update_count`；触摸帧不会覆盖实际位置或推进
`position_update_count`。

`k230_uart_decode_ball_x()` 只接受 `Flag=0x00`；
`k230_uart_decode_touch_x()` 只接受 `Flag=0x0A`。`my_menu_proc()` 每次在
`k230_app_service()` 后调用 `question_app_process_k230_touch()`。该函数在
所有题号都推进已见触摸计数，防止 Q0～Q5 收到的旧点击在后来切到 Q6 时被
误用；只有当前题号为 Q6 且业务状态为 `IDLE` 时才锁存新的合法 `Touch_X`。
K230 三连发的相同目标只造成一次目标变化；发车后的触摸帧仍被消费，但不改变
本次运行目标。

当前应用层使用以下接口初始化、持续消费并复制最新实际位置：

```c
#include "code/k230_app.h"

k230_app_snapshot_struct snapshot;
uint16 ball_x;
uint8 target_changed;

/* my_menu_init() 内，3 ms PIT 启动前。 */
(void)k230_app_init();

/* my_menu_proc() 每次调用的第一项，先于题目状态判断。 */
k230_app_service();
target_changed = question_app_process_k230_touch();

if (ZF_TRUE == k230_app_get_snapshot(&snapshot)
    && ZF_TRUE == snapshot.position_valid)
{
    ball_x = snapshot.ball_x;
}
```

Q3 启动目标为 `546U`，命中 `[526U,546U]` 后切到 `234U`；Q4/Q5 为
`396U`。Q6 没有固定目标：未收到合法 `Touch_X` 时菜单显示
`Q6 C:<pulse> AUTO BX`，`KEY_4` 锁存发车前最新有效 `Ball_X`；若此时也没有
有效 `Ball_X`，才返回 `QUESTION_APP_STATUS_TARGET_NOT_SET`。收到触摸目标后更新
`question_app_snapshot.ball_target_x` 并显示 `Q6 C:<pulse> READY T:<Touch_X>`。
Q6 `IDLE` 的 `KEY_2/KEY_3` 分别把 RAM 运行中心减/加 `20 pulse`；`KEY_4` 以锁存
目标和当前运行中心启动循迹与滚球，中心与 Target 数值无关。发车后目标和中心冻结，
后续触摸帧不调用 `ball_control_set_target()`。`target_x` 不属于 `k230_uart`
或 `k230_app`，是否采用触摸值由 `question_app` 决定。

`k230_uart_read_frame()` 只接受固定 5 字节帧；应用层还会拒绝超出 `0..799`
范围的 `Ball_X` 和 `Touch_X`。范围内的 `Ball_X` 直接发布，不进行相邻帧跳变过滤。
运行态不逐帧输出无线诊断，
需要定位控制问题时应在前台低频读取滚球控制快照。包尾错误时可通过
`k230_uart_get_frame_error_count()` 读取累计次数；计数饱和后保持
`0xFFFFFFFF`。

环形缓冲区可保存 127 字节，即 25 个完整 5 字节帧。一次点击的三连发占
15 字节。`k230_app_service()` 每次前台调用最多处理 27 个完整帧，因此单次
调用有确定上界；`Flag=0x0A` 更新独立触摸快照，仍不会覆盖实际位置快照。
可通过 `k230_uart_get_rx_overflow_count()` 检查接收溢出。

## 6. TC264 向步进电机发送命令

步进驱动器使用 Emm_V5 字节协议。所有帧以地址开头、以 `0x6B` 结尾，多字节字段高字节先发。底层 `stepper_uart` 只保留初始化所需的使能/停止、实时速度/绝对位置命令，以及固定最近点回零触发帧；单电机业务统一经 `step_motor` 调用，驱动器地址固定为 `0x01`。工程允许 Q0 `KEY_2` 触发回到驱动器外部既有机械零点，但写当前位置、设置零点、修改回零配置、中止回零及原始帧公开入口均不存在。

### 6.1 当前软件分层

| 层级 | 当前职责 |
| --- | --- |
| `stepper_uart` | UART3 配置、Emm_V5 组帧、初始化期阻塞发送，以及固定最近点回零、速度和绝对位置固定帧的非阻塞 FIFO 写入；原始写帧仅为本文件私有函数 |
| `step_motor` | 单电机地址、初始化安全序列、命令互斥、固定最近点回零触发、速度和绝对位置业务接口；不提供写当前位置、设置零点或修改回零配置接口 |
| `ball_control` | 每 18 ms 检查 K230 快照，只在新坐标上更新速度并推进位置式速度 PI；每三个有效内环更新一次位置 PI 外环，名义 54 ms；位置积分窗口和 I 限幅取当前题号参数表（Q3 为 `±82 px`/`±70 pixel/s`，Q4/Q5 和 Q6 均为 `±60 px`/`±30 pixel/s`）；Q3 关闭加速度前馈，Q4/Q5 和 Q6 使用各自表内前馈配置；Q3 使用固定 `+85/-100 pulse` 起滚阈值，Q4/Q5 与 Q6 共用 `+80/-80 pulse`；Q6 装载停车态提交的 RAM 绝对中心，同时完成 56 Hz 跨帧时间修正、目标速度/两级积分限幅、运行中心叠加、绝对软限位和最新目标重试；无新坐标时保持使能和串级状态，不自动回中或关闭 |

当前实时调用链为：

```text
Trigger_Return()
    → stepper_uart_try_start_home()
    → stepper_uart_try_write()
    → UART3 TX FIFO

Step_Motor_Set_Speed()
    → stepper_uart_try_run_velocity_signed()
    → stepper_uart_try_write()
    → UART3 TX FIFO

Step_Motor_Set_Position()
    → stepper_uart_try_move_signed()
    → stepper_uart_try_write()
    → UART3 TX FIFO
```

实时命令必须统一经 `step_motor` 调用；`stepper_uart` 不公开原始帧写入口，避免绕过本模块的互斥锁和最近命令时间记录。

### 6.2 当前常用帧

| 功能 | 帧格式 | 当前上层接口 |
| --- | --- | --- |
| 使能 | `01 F3 AB 01 00 6B` | `Step_Motor_Init()` 内部发送 |
| 最近点回零触发 | `01 9A 00 00 6B` | Q0 `KEY_2` 调用 `Trigger_Return()` |
| 速度 | `01 F6 Dir Speed_H Speed_L Acc 00 6B` | `Step_Motor_Set_Speed()` |
| 绝对位置 | `01 FD Dir 01 F4 00 Pulse_BE32 01 00 6B` | `Step_Motor_Set_Position()` |
| 停止 | `01 FE 98 00 6B` | `Step_Motor_Init()` 安全序列内部发送；底层也提供 `stepper_uart_stop()` |

速度和位置的正数映射 `CW=0x00`，负数映射 `CCW=0x01`，线上发送绝对值。绝对位置接口固定为：

- 绝对位置模式 `STEPPER_UART_POSITION_ABSOLUTE`；
- 位置速度字段 `500`；当前 Emm 驱动器已启用 `S_Vel_IS`，实际为 `50.0 RPM`；
- 加速度字段 `0`；
- 不使用多机同步。

`Step_Motor_Set_Speed(0)` 发送的是零速度 `F6` 帧，不是 `FE` 停止帧。当前 `step_motor` 没有公开运行期停止接口；滚球无新坐标时保持使能、PID 状态和最新绝对位置请求，不发送自动回中或停止命令。

### 6.3 初始化

K230 与步进底层分别初始化。当前 `my_menu_init()` 在 3 ms PIT 启动前调用
`ball_control_init()`，其内部执行阻塞式 `Step_Motor_Init()`；随后调用
`k230_app_init()`。不要在其它入口重复初始化 UART1 或 UART3：

```c
#include "code/ball_control.h"

if (BALL_CONTROL_STATUS_OK != ball_control_init())
{
    /* 不进入滚球控制。 */
}
```

`Step_Motor_Init()` 的实际顺序为：

1. 初始化 UART3，并关闭 RX/TX 中断；
2. 等待驱动器上电 `500 ms`；
3. 使能地址 `0x01`；
4. 等待 `10 ms`；
5. 发送停止帧；
6. 仅在停止帧成功交给本地发送层后标记初始化完成。

初始化不自动回零。Q0 `IDLE` 的 `KEY_2` 调用 `Trigger_Return()`，只发送固定帧 `01 9A 00 00 6B`，触发回到驱动器外部既有机械零点；`KEY_3` 只调用绝对位置接口推进固定脉冲机构测试。工程没有当前位置清零、设置零点、修改回零配置、中止回零或原始帧发送接口。`OK` 只表示本地帧已装入发送 FIFO，不表示驱动器已经开始移动、完成回零或到位。

### 6.4 周期速度与位置命令

```c
status = Step_Motor_Set_Speed(signed_speed);
status = Step_Motor_Set_Position(final_absolute_pulse);
```

回零、速度和位置接口都不阻塞等待 FIFO，也不排队旧命令。UART3 TX FIFO 非空或命令锁已被占用时立即返回 `STEPPER_UART_STATUS_TX_BUSY`；速度/位置控制器在后续控制拍重试最新目标。Q0 `KEY_2` 回零触发和 `KEY_3` 绝对位置测试在 `TX_BUSY` 时不推进本地状态，用户再次短按才重试。

115200 bit/s、8N1 下：

- 5 字节回零触发帧在线约 `0.43 ms`；
- 8 字节速度帧在线约 `0.69 ms`；
- 13 字节位置帧在线约 `1.13 ms`。

三种运行期固定帧都能一次装入 16 字节 UART3 TX FIFO。命令锁、其它发送或调用时刻仍可能使接口返回 `TX_BUSY`。初始化接口仍是阻塞式；Q0 的回零触发和固定脉冲测试都只由停车态前台按键调用，不放入控制 ISR；Q0 `KEY_2` 只触发驱动器回到既有机械零点，不写当前位置、不设置零点，也不修改回零配置。

速度字段虽然以 `rpm` 命名，但源码不做 `×10` 或 `÷10` 换算。当前 X42S 使用 Emm 固件且 `S_Vel_IS=Enable`，因此字段 `500` 实际是 `50.0 RPM`；手册 V1.0.5 的 Emm `F6/FD` 帧规定字段范围为 `0..3000`，源码按该原始字段范围校验。`Step_Motor_Set_Position()` 的参数是以驱动器外部既有机械零点为基准的最终绝对脉冲，不是像素误差、PID 原始输出或相对增量。

Q0 固定脉冲测试序列为：

```text
0,+20,+40,...,+200,0,-20,-40,...,-200
```

正脉冲序列连续递增到 `+200` 后回一次 `0`，再连续推进负脉冲序列。成功发送
后每 `150 ms` 输出 `PT,ID,EL,RQ,AP,MS,PV,BX,DX,PU,DU`；其中 `RQ/AP`
是请求和本地发送层接受的位置，不是驱动器回读。非零位置时禁止直接 `KEY_1`
切题或 `KEY_4` 启动，必须先继续按 `KEY_3` 走到下一次 `0`，或用 `KEY_2` 触发回到驱动器既有机械零点；回零帧成功进入 FIFO 后仅重置本地测试状态，不代表机构已经完成回零。

### 6.5 单向通信边界

UART3 不接驱动器 TX，没有 RX 缓冲、ACK、状态解析或遥测读取。所有 `OK` 只表示本地参数检查和发送动作成功，不能证明驱动器在线、已使能或达到目标位置。

调用方必须另行确认：

- 驱动器外部既有机械零点与摆杆机械中位的对应关系；
- 电机脉冲到连杆位移、摆杆角度的标定；
- 水管允许角度和连杆行程对应的脉冲软限位；
- K230 像素坐标到钢球物理位置的标定；
- 图像暂时无新坐标时的保持与恢复行为，以及 PID 数值错误、连续 `TX_BUSY` 时的实物表现。

速度估计只在新坐标到达时更新：

```text
elapsed_control_s = elapsed_inner_slots * 0.018
camera_interval_s = position_update_delta / 56.0
velocity_dt_s = max(elapsed_control_s, camera_interval_s)
raw_velocity_pixel_per_s =
    (actual_x - previous_fresh_actual_x) / velocity_dt_s
filtered_velocity_pixel_per_s +=
    parameters.velocity_filter_alpha
        * (raw_velocity_pixel_per_s
           - filtered_velocity_pixel_per_s)
```

位置外环每三个有效内环时隙更新目标速度。仅在小误差窗口内累计位置积分，
窗口外冻结已有积分；第一帧没有完整外环 `dt`，因此只计算 P：

```text
position_error =
    clamp(target_x - actual_x,
          -parameters.position_error_limit_pixel,
          +parameters.position_error_limit_pixel)
if abs(position_error) <= parameters.position_integral_window_pixel
        and outer_dt_s > 0:
    position_integral_velocity_pixel_per_s =
        clamp(previous_position_integral
              + parameters.position_outer_ki
                    * position_error * outer_dt_s,
              parameters.position_integral_min_velocity_pixel_per_s,
              parameters.position_integral_max_velocity_pixel_per_s)
else:
    position_integral_velocity_pixel_per_s =
        previous_position_integral
target_velocity_pixel_per_s =
    clamp(parameters.position_outer_kp * position_error
          + position_integral_velocity_pixel_per_s,
          -parameters.target_velocity_limit_pixel_per_s,
          +parameters.target_velocity_limit_pixel_per_s)
```

每个获得新速度的 18 ms 名义内环时隙执行位置式速度 PI：

```text
velocity_error =
    target_velocity_pixel_per_s - filtered_velocity_pixel_per_s
integral_output_pulse =
    clamp(previous_integral_output_pulse
          + parameters.velocity_inner_ki
                * velocity_error * elapsed_control_s,
          parameters.velocity_integral_min_pulse,
          parameters.velocity_integral_max_pulse)
velocity_pi_output_pulse =
    clamp(parameters.velocity_inner_kp * velocity_error
          + integral_output_pulse,
          min_pulse - center_pulse
              + parameters.acceleration_feedforward_output_limit_pulse,
          max_pulse - center_pulse
              - parameters.acceleration_feedforward_output_limit_pulse)
acceleration_feedforward_pulse =
    feedforward_allowed
        ? slew_limit(
              parameters.acceleration_feedforward_gain_pulse_per_lsb
                  * deadband_and_clamp(corrected_acc_y_lsb),
              previous_acceleration_feedforward_pulse)
        : 0
final_absolute_pulse =
    clamp(center_pulse
          + velocity_pi_output_pulse
          + acceleration_feedforward_pulse,
          min_pulse,
          max_pulse)
```

两级积分限幅约束的都是已经乘过各自 `Ki` 的 I 输出；通用 `pid_step()` 会在
总输出饱和时阻止积分继续推向同一方向，同时允许反向积分释放饱和。位置式 PI 总输出不
累加到旧位置目标。正脉冲在线上映射 `CW`，负脉冲映射 `CCW`；实物负反馈
方向由摄像头坐标、电机和连杆共同决定。
