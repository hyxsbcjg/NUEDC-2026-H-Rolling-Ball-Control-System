# TC264 工程协作规则

## 适用范围

本文件适用于整个 `Seekfree_TC264_Opensource_Library` 工程。当前目标为 TC264D、逐飞库 V3.4.4 和 C99。

以当前源码为准；接口、资源和移植结论详见 `code/逐飞库驱动层开发规范与调用指南.md`。编译结果不能代替入口可达性或上板验证。

## 文档目录与同步门禁

工程根目录固定为
`D:/myStudy/TC264/Can_Use/use_normal`。下列路径均相对该
目录；本清单覆盖当前工程内全部由项目维护的 `.md` 文档。`.txt` 不属于同步
维护范围，也不得作为当前设计真值。新增、删除、移动或重命名 Markdown 时，
必须在同一批改动中更新本清单、所有交叉引用，以及
`.settings/org.eclipse.core.resources.prefs` 中对应的 UTF-8 编码声明。

### 同步完成条件

- 代码是运行事实来源，文档必须描述同一份当前代码；发现冲突时不得以旧文档
  覆盖源码，也不得在冲突未解决时宣称任务完成。
- 每次改动后必须搜索旧宏、旧数值、旧引脚、旧速率、旧 API 名和旧路径，确认
  它们已从受影响的 Markdown 中删除；不维护的文本资料不能作为保留旧方案的
  理由。
- 旧方案直接删除，不保留“已弃用但仍像现行方案”的并列描述；未验证内容明确
  标为待验证，不能把计划写成已经完成的事实。
- 交付说明必须列出本次同步过的文档；若某份现行文档经检查确实不受影响，也要
  在内部完成影响判断，不得遗漏检查。
- 任何应同步的文档尚未更新，都视为本次代码改动未完成。

## 修改边界

- 新增驱动、板级适配和业务代码直接放入 `code`，不要创建子目录。
- 主机测试、桩头文件、源码备份和编译副本必须放在工程根目录之外的
  `D:/myStudy/TC264/tmp`；本工程的根源目录会递归收集 `.c`，不得在工程内
  `tmp` 放置任何测试或备份源码，否则 ADS 会把副本编入固件并产生重复定义。
- `libraries`、`user/isr_config.h`、链接脚本、`.cproject` 和 `Debug` 均禁止修改。
- 未经用户单独授权，不修改 `user/cpu0_main.c`、`user/cpu1_main.c` 或 `user/isr.c`。
- 获准修改 `user/isr.c` 时，只在向量函数中清中断标志并调用一个应用层回调；固定周期采样、PID 和实时控制放在 `code` 回调内，不把业务实现散落到 `user/isr.c`。
- 不启动或控制 ADS 等桌面软件。需要图形界面构建或下载时，只给出步骤，由用户执行；除非用户重新明确授权。
- 保留用户已有改动，不覆盖无关文件。

## 文件编码

- 工程默认编码固定为 `GBK`，与逐飞 `user`、`libraries` 和 ADS 工程设置一致。
- `code` 下 `.c`、`.h`、`.txt` 一律使用无 BOM 的 GBK；不要再保存为 UTF-8，否则 ADS 会把中文注释显示为乱码。
- Markdown 文档使用无 BOM 的 UTF-8，并在 `.settings/org.eclipse.core.resources.prefs` 中逐文件声明为 UTF-8。
- 修改遗留文件时必须按其既有编码解码、再以同一编码写回；严禁用错误编码读出乱码后再保存。

## 代码规则

- 优先复用公开的 `zf_driver`、`zf_device` API，不复制底层驱动，不为适配硬件而修改逐飞库。
- 每个模块使用独立前缀；宏用大写，公开声明放在 `.h`，实现和私有命令放在 `.c`。
- `.c` 先包含本模块头文件。使用逐飞类型 `uint8`、`uint16`、`uint32`，常量写明无符号后缀。
- 单板固定的地址、引脚、速率和超时使用头文件宏；确有多实例或多板型需求时才增加运行时配置结构。
- 检查空指针、长度、通道范围、初始化状态和底层返回值。等待与重试必须有上限。
- CPU0 使用的静态或全局状态显式放入 `cpu0_dsram`，并在 pragma 恢复后定义函数。
- 3 ms PIT 每拍先独立采样 IMU 和灰度；`gray_app_read()` 在采样层直接把 `error`
  更新为新样本权重 `0.3` 的一阶低通结果，task、显示和控制只使用该滤波值，
  不得在消费者中二次滤波。Q0 的编译期自定义模式当前选择 `SOFT_START`：
  `KEY_4` 发车后先用 Q4/Q5 滚球参数保持 `Ball_X=396`，同时只给默认物理左轮
  `500`；CH2 首次检测到黑线后，车体先在约 2 s 内从 `500/0` 过渡到
  `1000/1000`，再在约 2 s 内过渡到 `1700/1700`。IMU/灰度仍每 3 ms 采样，
  滚球保持 18/54 ms 串级调度。题目 2 发车后，先逐帧
  处理停车线，再让控制处理复用本拍数据：角速度内环每 6 ms 执行，灰度外环
  每 12 ms 执行。共同到期拍按“采样 → Q2 航向/计时 → 停车线业务 → 外环 PD →
  内环 PD → 电机输出”完成。Q2 的 `KEY_4` 成功后从首个 3 ms 运行拍开始累计
  比赛时间和校零 Z 轴航向；绝对累计航向达到 `300 deg` 时，通过运行态接口把
  基础 PWM 从 `3200` 切到 `800`，不清除两级 PID 历史。第一次停车线只进入
  冷却，第二次确认拍计入并冻结、停车。运行态不写屏，完成后的前台刷新把毫秒
  值截断为百分之一秒并显示 `TIME:ss.ccs`。Q2 通过普通入口立即采用基础 PWM
  `3200`。所有题号均不做出界/丢线自动停车，`track_control_enable*()` 不再接收
  丢线停车策略参数。发车后尚未取得有效灰度时，目标角速度保持 0 并按基础 PWM
  直行；取得有效目标后，`error_num == 0`、灰度状态异常或空样本都只跳过外环并
  保持最后一次有效目标。IMU/零偏无效或 PID 错误时沿用上次有效差速修正（初值
  为 0）继续输出，电机接口错误只记录状态并在后续周期重试，均不得自行禁用控制
  或调用停车。Q4/Q5/Q6 通过 `track_control_enable_ramp(400, 1700, 350)` 软启动，只在一次
  有效 6 ms 内环确实完成两路电机输出后推进一个周期。第 1 次精确输出 `400`，
  第 350 次精确达到并保持 `1700`，名义软启动时间约 `2.1 s`；Q3 不启动车体
  循迹。Q3 发车后先以 `546` 为滚球目标；
  控制器消费到的有效实际位置
  首次进入闭区间 `[526,546]` 后，题目状态单向切换到目标 `234` 并持续稳定，
  不返回 `546`，只在重新启动或复位 Q3 时重置。`ball_control_set_target()`
  立即刷新位置外环的比例目标，但保留两级 PI 积分、速度历史、使能状态和电机
  请求。Q4/Q5/Q6 执行相同的 6/12 ms 车体循迹，并与滚球串级控制并行；三题不进入
  Q2 停车线状态机，不做比赛计时、过点/圈数完成判定或正常完赛自动停车，裁判
  在车外计时。运行中暂时没有新 `Ball_X` 时不得关闭滚球、清空串级状态或请求
  中位；必须保持使能和最新绝对位置请求，新坐标恢复后继续闭环。滚球 PID/非
  `TX_BUSY` 电机接口错误仍只关闭滚球自身并请求中位，`question_app` 保持
  `RUNNING` 且不关闭车体循迹；当前唯一自动停车路径是 Q2
  第二次停车线确认调用 `track_control_disable()`。题目 3～6 使用“位置 PI 外环 →
  速度位置式 PI 内环”的滚球串级控制：每 18 ms 进入一次内环时隙，但只有
  `position_update_count` 标识新 K230 坐标时才更新速度并推进速度 PI；位置
  外环每三个已消费的新坐标更新一次目标速度，名义周期 54 ms。位置积分按各题号
  参数表的积分窗口和输出限幅执行，窗口外冻结；首个新坐标没有完整外环 `dt`，只建立速度历史并执行
  位置 P。第二个新坐标才产生首个速度 PI 输出；重复快照保持目标速度、两级积分
  和电机请求。速度观察时间取“实际控制间隔”和“56 Hz 帧计数间隔”中的较大值，
  速度 PI `dt` 使用两次实际执行间隔。位置误差限幅为 `[-10000,+10000] px`，
  目标速度限幅为 `[-1000,+1000] pixel/s`；速度 PI 积分输出限幅按参数表选择，
  Q3 为 `[-80,+80] pulse`，Q4/Q5 和 Q6 为 `[-130,+130] pulse`。三套表
  当前的前馈状态为：Q3 输出限幅为 `0`（关闭），Q4/Q5 和 Q6 输出限幅为
  `100`；调度器仅在上述 350 周期车体缓启动尚未完成时允许两套前馈，斜坡
  完成后的首个 18 ms 滚球槽将前馈目标和输出清零。Q0 `SOFT_START` 不允许
  前馈，Q0 `ACCEL_FF` 专项调试仍强制允许。钢球近似静止且 `|位置误差|>15 px` 时，直接按位置误差方向
  把控制量提高到当前题号的起滚下限。Q3 固定使用 `+85/-100 pulse`；Q4/Q5
  和 Q6 共用 `BALL_CONTROL_Q4_Q5_BREAKAWAY_POSITIVE_MIN_PULSE=+80 pulse` 与
  `BALL_CONTROL_Q4_Q5_BREAKAWAY_NEGATIVE_MAX_PULSE=-80 pulse`。Q6 运行中心与 Target
  完全独立：停车态 `KEY_2` 每次把 RAM 绝对中心减 `20 pulse`，`KEY_3`
  每次加 `20 pulse`；只有绝对位置命令成功进入本地 FIFO 后才提交新中心。
  Q6 发车后使用“该运行中心 + 控制器输出”，运行中心不是机械零点，也不写入
  驱动器零点或回零配置。静止速度阈值
  为 `±30 pixel/s`，运动中的反向
  制动不做补偿。原单环 PV 不再调用。无新位置时不推进位置/速度 PI，但必须保持
  滚球使能、两级 PI 状态、速度历史和最新绝对位置请求，不设置失新超时、不自动
  回中或关闭；后续新位置到达后按累计间隔继续闭环。所有 ISR
  步骤必须有确定上界并实测最坏执行时间。
- Q2 每次停车线确认都要求连续两个 3 ms 样本同时满足 `error_num >= 4`、`digital_value` bit3=0 和 bit4=0，即 CH4、CH5 都为黑线；其它通道可以同时为黑线。灰度状态异常、空样本、黑线数不足或任一中心通道为白都会把连续计数清零。冷却期忽略样本并保持连续计数为零。
- 显示、日志、Flash、显式延时、K230 成帧和其它非实时业务留在前台。`my_menu_proc()` 必须先于题目状态门控调用 `k230_app_service()`，使停车态和发车态都持续消费 UART1；当前 K230 800 像素显示坐标的合法范围为 `0..799`，超范围 `Ball_X` 不发布到滚球控制器；范围内的每个合法 `Ball_X` 都直接发布并递增 `position_update_count`，不做相邻帧跳变过滤；当前运行态不对每个位置帧调用 `my_printf()`，诊断输出必须在前台低频读取控制快照，不能进入 18 ms 控制 ISR。运行态仍禁止写屏。步进初始化/配置使用前台阻塞接口；Q0 的 `KEY_2` 只在前台调用 `Trigger_Return()`，非阻塞发送固定最近点回零帧 `01 9A 00 00 6B`，触发驱动器回到外部既有机械零点；发送成功后重置 Q0 测试状态。该路径不得写当前位置、设置零点或修改回零配置。Q6 `IDLE` 的 `KEY_2/KEY_3` 分别请求当前 RAM 运行中心 `-20/+20 pulse` 的新绝对位置，成功发送后才提交新中心；失败不改中心且不自动重试。Q0 `IDLE` 的 `KEY_3` 在前台按 `0,+20,+40,...,+200,0,-20,-40,...,-200` 只推进绝对脉冲机构测试，并每 `150 ms` 输出一行 `PT` 遥测；非零测试位置禁止 `KEY_1` 切题和 `KEY_4` 启动，必须继续按 `KEY_3` 走到序列中的下一次 `0`，或用 `KEY_2` 触发回零。控制 ISR 只允许调用专门的非阻塞速度/位置接口。工程只允许固定的最近点回零触发，不得公开或实现当前位置清零、设置回零零点、修改回零配置、回零输入模式、中止回零或原始帧发送入口；Q6 RAM 运行中心不是机械零点，机械零点只能由驱动器外部既有配置决定。
- 初始化顺序为：清状态、设置安全态、初始化总线、初始化设备、验证设备、最后开启异步事件源。

## 标准移植流程

每次移植按以下顺序执行，不跳过分析、资源登记或验证：

1. **固定基线**：记录目标芯片、工程、逐飞库、编译器、设备型号、手册版本和参考工程路径。
2. **追踪参考实现**：从入口追到初始化、收发、延时、回调和错误处理，分清底层驱动与业务逻辑。
3. **整理协议表**：列出地址或帧头、命令、方向、长度、时序、返回值、错误码和持久化副作用。
4. **映射目标 API**：逐项核对函数签名、参数顺序、地址语义、阻塞性、返回值、ACK、FIFO、回调和中断行为。
5. **登记资源**：固定实例、引脚、硬件通道、中断、优先级、服务核、唯一所有者、安全态、速率和冲突。
6. **确定移植边界**：列出本次包含与暂不包含的功能；固定板级参数用宏，公开接口保持最小。
7. **编写驱动**：在 `code` 平铺新增 `.h/.c`；头文件放配置、状态和公开 API，源文件放私有命令、状态和实现。
8. **处理可靠性**：检查参数和返回值；限制缓冲区、等待和重试；保留目标库的流控、FIFO、超时和错误语义。
9. **设计接入点**：给出 `app_init()`、前台任务和最小 ISR 回调的调用方式；未经授权不修改入口或中断文件。
10. **执行静态验证**：检查声明/实现、旧平台符号、危险接口、无限循环、无界格式化、地址重复转换和资源冲突。
11. **列出目标验收步骤**：由用户在 ADS 中执行 F5、Clean、Build；代理只记录用户提供的构建日志、产物时间、Map 和入口证据。
12. **完成上板与记录**：验证电平、接线、波形、设备身份、正常收发、超时、复位和故障恢复；随后更新移植记录。

### 总线专项检查

- **IIC**：确认 7 位/8 位地址、读写位、重复 START、ACK 可见性、上拉电压、总线速率和上电等待。
- **UART**：确认实例、波特率、数据位、校验、停止位、TX/RX 方向、RTS/CTS、ISR/FIFO、帧格式、字节序、校验和与接收超时。

移植记录统一写入 `code/逐飞库驱动层开发规范与调用指南.md`，至少包含基线、协议映射、资源、适配结论、调用示例、验证边界、电气约束和复用清单。

## 验证与交付

- 先做声明/实现一致性、危险接口、无限循环、无界格式化和资源冲突扫描。
- 分开记录：C99 静态检查、TASKING 编译、链接、Map 符号、入口可达性和上板结果。
- 被验证的源码发生变化后，旧的 C99、TASKING、链接和 Map 记录全部失效，必须重新验证。
- 只有构建日志无错误，且对象文件、ELF、HEX、Map 均晚于最新源码，才能写“TASKING 编译链接通过”。
- Map 中存在符号只证明已链接；标记为 `unreferenced` 时，运行入口仍未接通。
- 没有实物波形、通信或读数证据时，只能写“待上板验证”。
